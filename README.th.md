# ai-hub

[English](README.md) · **ภาษาไทย**

คำสั่งเดียวสำหรับ AI coding agent ทุกตัว พิมพ์ `ai` แล้วจะเห็นรายชื่อ agent และบัญชีทั้งหมด พร้อมแถบแสดงโควตาที่ใช้ไป จากนั้นเลือกตัวที่ต้องการเพื่อเปิดในโฟลเดอร์ปัจจุบัน

- **ทุก agent ในรายการเดียว** Claude Code (หลายบัญชี), Codex (หลายบัญชี), Antigravity CLI (`agy`), Gemini, Qwen, OpenCode, Kimi หรือ CLI อะไรก็ได้ที่เพิ่มเอง
- **ดูโควตาได้ทันที** แสดงลิมิต 5 ชั่วโมงและรายสัปดาห์พร้อมเวลารีเซ็ต แถบเป็นสีเหลืองที่ 60% และสีแดงที่ 90%
- **หลายบัญชี Claude** เพิ่ม ลบ เปลี่ยนชื่อได้อย่างปลอดภัย การลบคือย้ายไปถังขยะ ไม่มีอะไรหายจริง
- **แชร์ folder trust** (ปิดไว้เป็นค่าเริ่มต้น) trust โฟลเดอร์ครั้งเดียว agent ทุกตัวไม่ต้องถามซ้ำ
- **หลายบัญชี Codex** ทำได้แบบเดียวกันด้วย `ai codex`
- **Failover** (ปิดไว้เป็นค่าเริ่มต้น) เมื่อบัญชี Claude ชนลิมิต ทำงานต่อใน session เดิมบนบัญชีถัดไป และส่งงานต่อให้ Codex ได้ถ้าเพิ่ม Codex เข้าไปในลำดับ
- **ทีม agent** (ปิดไว้เป็นค่าเริ่มต้น) หัวหน้าทีมที่คุณคุยด้วยจะทำงานที่ตัวเองถนัด ส่วนที่เหลือกระจายให้ agent และบัญชีอื่นด้วย `ai delegate` แล้วตรวจผลงานที่ได้กลับมา และสมาชิกแต่ละคนมีทีมของตัวเองได้ สมาชิกเริ่มแบบประหยัดและรายงานกลับสั้นๆ เพื่อประหยัด token และถ้าโควตาหมดกลางงาน จะส่งงานพร้อมสิ่งที่ทำไปแล้วต่อให้สมาชิกคนถัดไปที่ว่าง ตั้งค่าด้วยการตอบคำถาม (`ai team setup`) แล้วสั่งงานเป็นภาษาปกติด้วย `ai do "..."`
- **ไม่เรียก API ใดๆ** ข้อมูลโควตาอ่านจากไฟล์ที่ agent เขียนไว้ในเครื่องอยู่แล้ว

รองรับ macOS, Linux และ WSL เขียนด้วย bash ล้วน (ใช้ได้กับ bash 3.2 ที่มากับ macOS)

## ติดตั้ง

ดาวน์โหลด repo นี้ (ปุ่ม **Code → Download ZIP**) แตกไฟล์ไว้ที่ไหนก็ได้ เช่น `~/ai-hub` แล้วรัน:

```bash
cd ~/ai-hub
bash install.sh        # สร้างลิงก์ ai และ cla ไว้ใน ~/.local/bin
bash tests/run.sh      # ทดสอบก่อนใช้จริง ต้องขึ้น "all passed"
```

เครื่องมือเสริม (ไม่ติดตั้งก็ใช้ได้ แต่ฟีเจอร์บางอย่างจะปิด):

| เครื่องมือ | เพิ่มอะไร |
|---|---|
| [jq](https://jqlang.org) | แถบโควตา, แชร์ trust, failover (มีใน macOS 15+ แล้ว) |
| [fzf](https://github.com/junegunn/fzf) | ตัวเลือกแบบค้นหาได้ ถ้าไม่มีจะเป็นเมนูตัวเลข |

```bash
brew install jq fzf              # macOS
sudo apt install jq fzf          # Linux / WSL
```

### เปิดการแสดงโควตาของ Claude

Claude Code ส่งข้อมูลโควตาให้ status line ใส่ใน `~/.claude/settings.json`:

```json
"statusLine": { "type": "command", "command": "bash ~/ai-hub/scripts/statusline-usage.sh" }
```

ถ้ามี status line เดิมอยู่แล้ว ใส่คำสั่งเดิมต่อท้ายได้ สคริปต์จะส่งข้อมูลต่อให้:

```json
"statusLine": { "type": "command", "command": "bash ~/ai-hub/scripts/statusline-usage.sh my-statusline --flag" }
```

ตัวเลขจะขึ้นหลัง Claude ตอบครั้งถัดไป และมีเฉพาะแพ็กเกจ Pro/Max เท่านั้น บัญชีที่สร้างด้วย `cla add` ใช้ `settings.json` ร่วมกัน จึงตั้งครั้งเดียวพอ

## ใช้งาน

```bash
ai                 # เลือก agent แล้วเปิดในโฟลเดอร์นี้
ai --resume        # อาร์กิวเมนต์ที่เหลือส่งต่อให้ agent
ai ls              # ดูรายชื่อ agent และคำสั่งที่ใช้เปิด
ai add aider "aider --model sonnet" "Aider"
ai edit claude "claude --model opus"
ai rm aider
ai scan            # เพิ่ม agent ที่เพิ่งติดตั้งทีหลัง (claude codex agy gemini qwen opencode kimi)
```

รายชื่อเก็บใน `~/.config/ai-hub/providers` บรรทัดละหนึ่งตัว ตอนรันครั้งแรกจะใส่ agent ที่ติดตั้งอยู่ให้อัตโนมัติ ถ้าติดตั้งตัวใหม่ทีหลังให้รัน `ai scan` คำสั่งทำงานเหมือน shell alias จึงใส่ `VAR=value` นำหน้าได้ เช่น Codex บัญชีที่สอง:

```bash
ai add codex-work "CODEX_HOME=~/.codex-work codex" "Codex (work)"
```

แถบโควตาของ Codex อ่านจาก `CODEX_HOME` ในคำสั่ง เขียนเป็น `~/...` หรือ `$HOME/...` ก็ได้ ถ้ามี Codex หลายบัญชี ใช้ `ai codex` ด้านล่างจะง่ายกว่า

### หลายบัญชี Claude

```bash
cla add work       # สร้างบัญชี (settings, skills, plugins ใช้ร่วมกับบัญชีหลัก)
cla work           # เปิดบัญชีนั้น ครั้งแรก Claude จะให้ล็อกอิน
cla main           # บัญชีปกติ (~/.claude)
cla                # เลือกบัญชีจากรายการ
cla ls             # ดูว่าแต่ละบัญชีล็อกอินด้วยอีเมลอะไร
cla mv work job    # เปลี่ยนชื่อ
cla rm job         # ย้ายไป ~/.claude-accounts/.trash/ (ไม่ลบจริง)
```

### หลายบัญชี Codex

```bash
ai codex add work       # สร้างบัญชี (config.toml, AGENTS.md และ prompts ใช้ร่วมกับบัญชีหลัก)
ai codex work login     # ล็อกอินบัญชีนั้น (อาร์กิวเมนต์หลังชื่อบัญชีส่งต่อให้ codex)
ai codex work           # เปิดบัญชีนั้น
ai codex main           # บัญชีปกติ (~/.codex)
ai codex                # เลือกบัญชี Codex จากรายการ
ai codex ls             # ดูว่าบัญชีไหนล็อกอินแล้ว
ai codex mv work job    # เปลี่ยนชื่อ
ai codex rm job         # ย้ายไป ~/.codex-accounts/.trash/ (ไม่ลบจริง)
```

แต่ละบัญชีมี `CODEX_HOME` ของตัวเองใน `~/.codex-accounts/<ชื่อ>` (เปลี่ยนโฟลเดอร์ได้ด้วย `CDX_ROOT`) และขึ้นในตัวเลือกของ `ai` พร้อมแถบโควตาของตัวเอง ข้อมูลล็อกอินอยู่ในโฟลเดอร์ของบัญชีนั้น ai-hub แค่เช็คว่ามีไฟล์อยู่ ไม่เคยเปิดอ่าน

เมื่อลบบัญชี (`cla rm`, `ai codex rm`) หรือ agent (`ai rm`) ระบบจะเอาชื่อนั้นออกจากทุกทีมและจากลำดับ failover ให้ด้วย

### แชร์ folder trust

```bash
ai trust on        # เปิด
ai trust off       # ปิด
```

ก่อนเปิด agent ในโฟลเดอร์ใด ถ้ามี agent ตัวไหน (หรือบัญชี Claude ใด) trust โฟลเดอร์นั้นอยู่แล้ว ตัวอื่นจะถูกตั้งให้ trust ด้วย รองรับ Claude Code, Codex, Gemini และ Qwen ส่วน Antigravity CLI ไม่มีรายการโฟลเดอร์ที่ trust จึงไม่มีอะไรให้แชร์

### Failover

```bash
ai failover on
ai failover order work main personal   # ลำดับที่จะลอง บนสุดก่อน
ai failover status
ai failover clear work                  # ล้างสถานะติดลิมิต
```

เมื่อเห็นข้อความว่าชนลิมิตใน Claude ให้ออกจาก Claude (`/exit` หรือ ctrl-c สองครั้ง) แล้ว `ai` จะถามว่าจะทำงานต่อในบัญชีถัดไปไหม ถ้าตอบ `y` จะคัดลอก session ไปบัญชีนั้นแล้วเปิดด้วย `claude --resume` (กด Enter เฉยๆ คือไม่ย้าย)

- **ตรวจเฉพาะ session ของโฟลเดอร์นี้** เปิดบัญชีเดียวกันหลายหน้าต่างในโฟลเดอร์ต่างกันได้ ไม่หยิบ session ผิดตัว
- **ตัวเลือกที่พิมพ์ไว้ตามไปด้วย** เช่น `cla work --model opus` พอย้ายบัญชีจะยังใช้ `--model opus` ส่วน prompt, `--continue` และ `--resume` เดิมจะถูกตัดออก ถ้าตัวเลือกไหนมีค่าตามหลัง ให้เขียนแบบ `--option=value` จะชัวร์ที่สุด
- **บัญชีที่ชนลิมิตจะถูกข้ามจนถึงเวลารีเซ็ตจริง** ใช้เวลาจากข้อความ error หรือจากข้อมูลโควตาที่ status line บันทึกไว้ (ลิมิตรายสัปดาห์ก็ข้ามได้ถูก) ถ้าไม่รู้เวลารีเซ็ตจะข้ามไป 5 ชั่วโมง (เปลี่ยนได้ด้วย `AI_FO_COOLDOWN` หน่วยวินาที)
- **นับเฉพาะโควตาของแพลนที่หมด** rate limit ชั่วคราว (429) หรือ context เต็ม ไม่ถือว่าชนลิมิต

#### ส่งงานต่อให้ Codex หรือ agent อื่น

ใส่บัญชี Codex ในลำดับเป็น `codex:<ชื่อ>` หรือ agent จาก `ai ls` ที่ ai เปิดพร้อมบทสนทนาได้ (`agy` คือ Antigravity CLI, `gemini` หรือ `qwen` ส่วน CLI อื่นอาจอ่านบทสนทนาเป็นชื่อโฟลเดอร์หรือไฟล์) ปกติไว้ท้ายสุด เพื่อให้รับงานต่อเมื่อบัญชี Claude หมดทุกบัญชี:

```bash
ai failover order main work codex:main agy
```

ตัวเหล่านี้เปิด session ของ Claude ไม่ได้ จึงเปิดในโฟลเดอร์เดิม โดยส่งบทสนทนาที่ผ่านมาไปเป็นข้อความแรก ส่งเฉพาะสิ่งที่คุณกับ Claude พิมพ์ ไม่รวมการเรียก tool และผลลัพธ์ และตัดเหลือ 60 KB ล่าสุด (`AI_FO_HANDOFF_MAX`) ข้อความเปิดเปลี่ยนได้ด้วย `AI_FO_CODEX_PROMPT` ถ้า session นั้นเป็นหัวหน้าทีม (`ai team`) ข้อความจะบอกด้วยว่าเป็นหัวหน้าทีม และดูทีมได้อย่างไร

- **เป็นการส่งบทสนทนาไปผู้ให้บริการอีกราย** Codex หรือ agent จึงไม่อยู่ในลำดับจนกว่าคุณจะเพิ่มเอง และระบบถามทุกครั้ง (ค่าเริ่มต้นคือไม่ส่ง)
- **บัญชี Claude ของคุณมาก่อนเสมอ**: บัญชี Claude ที่ไม่ได้ระบุในลำดับ (รวมถึงบัญชีที่เพิ่มทีหลัง) จะถูกลองก่อน Codex หรือ agent ตัวแรก
- **ต่อจาก Codex ได้**: เมื่อออกจาก Codex ระบบจะอ่านไฟล์ session ของมัน (ไม่หยิบ `codex exec` เช่นงานที่กระจายในทีมมาแทน) ถ้า Codex หยุดเพราะโควตาแพลนหมด (จะถูกบันทึกว่าติดลิมิตจนถึงเวลารีเซ็ต) คนถัดไปจะได้บทสนทนาทั้งหมด รวมถึงสิ่งที่ Codex เขียนไว้ ถ้าคนถัดไปเป็นบัญชี Claude จะเปิด session ใหม่พร้อมบทสนทนานั้น และตัวเลือกเดิมของ session แรก (คำชี้แจงทีม `--model` ฯลฯ)
- **agent อื่นเป็นปลายทางสุดท้าย** ระบบบอกไม่ได้ว่ามันหยุดเพราะโควตาหมดหรือไม่
- ถ้าเริ่มจาก Codex หรือ agent อื่นจะไม่มี failover ใช้ได้เฉพาะตอนเริ่มจาก session ของ Claude

### ทีม agent

**วิธีที่ง่ายที่สุด**: ตอบคำถามครั้งเดียว จากนั้นสั่งงานเป็นภาษาปกติ ไม่ต้องจำคำสั่งอื่น

```bash
ai team setup                      # เลือกหัวหน้า สมาชิก แต่ละคนถนัดอะไร และโฟลเดอร์ที่ให้ใช้เพิ่ม
ai do "เพิ่ม dark mode พร้อม test"     # รันในโฟลเดอร์โปรเจค หัวหน้าจะวางแผนแล้วแบ่งงานให้ทีมเอง
```

**ให้ทีมตกลงกันเองว่าใครทำอะไร**: `ai team discover` ถามสมาชิกทุกคนพร้อมกันว่าถนัดอะไรที่สุด (โมเดล จุดแข็ง จุดอ่อน เร็วหรือละเอียด) เพิ่มข้อมูลที่ ai รู้เอง (ผู้ให้บริการ และใช้โควตาไปเท่าไร) แล้วให้หัวหน้าเสนอหน้าที่ของแต่ละคน ใครคุมทีมย่อย และใครรับแทนหัวหน้าเมื่อโควตาหมด คุณจะเห็นข้อเสนอพร้อมเหตุผล และไม่มีอะไรเปลี่ยนจนกว่าจะตอบ `y` (ทีมและลำดับ failover เดิมเก็บไว้เป็น `.bak`) ใช้ token แค่คำขอสั้นๆ คนละครั้งบวกของหัวหน้าอีกหนึ่ง และทำงานเฉพาะตอนที่คุณสั่ง ควรรันใหม่หลังเพิ่มสมาชิก หรือเมื่อโควตาของใครใกล้หมด `ai team discover <สมาชิก>...` ถามเฉพาะคนที่ระบุ สมาชิกคนอื่นคงตำแหน่งและหน้าที่เดิม ลำดับที่เสนอมาจะถูกตรวจ: ชื่อที่ไม่มีอยู่จะถูกตัด แต่ละคนอยู่ได้ครั้งเดียว และบัญชี Claude มาก่อน Codex และ agent อื่นเสมอ เพราะตัวอื่นได้บทสนทนาแค่เป็นข้อความ และส่งไปผู้ให้บริการอีกราย

`ai team setup` จะแสดงรายการบัญชีและ agent เป็นตัวเลข คุณแค่พิมพ์ตัวเลขเลือก (กด Enter = ใช้คำตอบในวงเล็บ) รันซ้ำเมื่อไหร่ก็ได้เพื่อเพิ่มสมาชิกหรือตั้งทีมใหม่ (ทีมเก่าเก็บไว้เป็น `.bak`) ถ้ายังไม่มีทีม `ai do` จะพาไปตั้งค่าก่อน ถ้าไม่ใส่งาน `ai do` จะถาม หัวหน้าทีมรัน `ai delegate`, `ai team wait` และ `ai team log` ได้โดยไม่ต้องถามคุณทุกครั้ง ทีมจึงทำงานต่อกันเองได้ คุณแค่ดูอยู่

คำสั่งข้างล่างคือสิ่งที่ setup ทำให้ ใช้เมื่ออยากแก้ทีละจุด

```bash
ai team add codex:main "refactor ใหญ่ เขียน test"
ai team add work2 "เขียนเอกสาร แก้จุดเล็กๆ"        # บัญชี Claude ที่สอง
ai team add agy "อ่าน codebase ขนาดใหญ่"            # agent ตัวไหนก็ได้จาก ai ls
ai team lead main                                  # หัวหน้าทีม คนที่คุณคุยด้วย (ค่าเริ่มต้น: main)
ai team                                            # เปิดหัวหน้าทีมในโฟลเดอร์นี้
ai team ls                                         # ดูหัวหน้าและสมาชิก
ai team log                                        # ดูว่ากระจายงานอะไรไปบ้าง ผลเป็นอย่างไร
```

`ai team` เปิดหัวหน้าทีม (Claude Code ตามปกติ) พร้อมแนบคำชี้แจงเข้าไปใน system prompt ว่าในทีมมีใครบ้าง แต่ละคนถนัดอะไร และจะส่งงานอย่างไร หัวหน้าจะทำงานที่ตัวเองถนัดเอง ส่วนที่เหลือจะรัน `ai delegate <สมาชิก> "<งาน>"` ซึ่งเปิดสมาชิกคนนั้นแบบไม่มีหน้าจอ (headless) ในโฟลเดอร์เดียวกัน (`claude -p`, `codex exec`, `agy -p`, ...) พิมพ์คำตอบกลับมาให้หัวหน้าอ่านต่อ และเก็บ log ฉบับเต็มไว้ อาร์กิวเมนต์อื่นส่งต่อให้หัวหน้า เช่น `ai team --model opus`

- **สมาชิกแก้ไฟล์ได้เอง แต่ทีละคนต่อโฟลเดอร์** งานที่สองจะรอให้งานแรกเสร็จก่อน agent สองตัวจึงไม่มีทางแก้ไฟล์เดียวกันพร้อมกัน
- **หัวหน้ายังรับผิดชอบผลงาน** คำชี้แจงบอกให้หัวหน้าตรวจสิ่งที่ได้กลับมา (รัน test ดู diff) แล้วแก้เองหรือส่งกลับไปทำใหม่
- **สมาชิกที่ชนลิมิตจะถูกปฏิเสธ** หัวหน้าจึงเลือกคนอื่นแทน
- **failover ไม่หยิบงานที่กระจายในทีมมาผิดตัว**: Claude แบบ headless (`claude -p`) ในโฟลเดอร์เดียวกันจะถูกข้ามตอนหา session ที่ชนลิมิต
- **สมาชิกที่ชนลิมิตระหว่างทำงานจะส่งงานต่อเอง**: ถูกบันทึกว่าติดลิมิตแบบเดียวกับ failover แล้วงานจะไปหาสมาชิกคนถัดไปที่ว่างในทีมเดียวกัน (เรียงตามลำดับ failover แล้วตามลำดับในทีม) พร้อมบอกให้ดู `git status` ก่อน และส่วนท้ายของสิ่งที่คนแรกเขียนไว้ (`AI_TEAM_HANDOFF_MAX` 4 KB) ทั้งสองรอบอยู่ใน log เดียวกัน และ `ai team wait` จะรอคนที่ทำจบ แล้วแสดงเฉพาะคำตอบของคนนั้น ปิดได้ด้วย `AI_TEAM_HANDOFF=0`
- **สมาชิกที่ไม่ตอบอะไรกลับมา** (เช่น ถูกปฏิเสธสิทธิ์ที่ถามไม่ได้) ระบบจะแสดงท้าย log ให้หัวหน้าเห็นว่าเพราะอะไร
- **ทุกอย่างมี log** `ai team log` แสดงรายการงานที่เคยกระจายไป ส่วนงานและคำตอบฉบับเต็มอยู่ใน `~/.local/state/ai-hub/team/logs/` ซึ่งอ่านได้เฉพาะคุณ log ของงานที่เสร็จแล้วจะถูกลบเมื่อเก่ากว่า 30 วัน (`AI_TEAM_KEEP_DAYS` ตั้งเป็น `0` ถ้าอยากเก็บไว้ตลอด) หรือลบทั้งหมดทันทีด้วย `ai team log --clean`
- `ai delegate -b <สมาชิก> "<งาน>"` รันเบื้องหลัง (ไฟล์ log จะลงท้ายด้วย `# done` เมื่อเสร็จ) `ai delegate <สมาชิก> -` รับงานยาวๆ จาก stdin และ `ai team brief` พิมพ์คำชี้แจงออกมา เผื่อเอาไปใช้กับ setup อื่น
- สมาชิกแต่ละคนใช้โควตาของตัวเอง การตั้งทีมจึงช่วยกระจายการใช้งานไปหลายบัญชีด้วย

#### ประหยัด token

สมาชิกทุกคนเสีย token ตามที่อ่านและเขียน ทีมจึงตั้งไว้ให้เปลืองน้อยที่สุด

- **สมาชิก Claude เริ่มแบบประหยัด**: มีแค่เครื่องมือที่ใช้เขียนโค้ด (`Read Edit Write Bash Glob Grep`) ไม่โหลด MCP server, skill หรือคำสั่งของ plugin วัดบน Claude Code 2.1 แล้ว สมาชิกเริ่มที่ราว 7.7k token แทนที่จะเป็น 24k ตั้ง `AI_TEAM_CLAUDE_LEAN=''` ถ้าอยากโหลดทุกอย่างเหมือนเดิม ส่วนหัวหน้าที่คุณคุยด้วยยังมีเครื่องมือครบเสมอ
- **รายงานสั้น**: ทุกงานลงท้ายด้วยการขอรายงานไม่เกิน 15 บรรทัด (เสร็จไหม แก้ไฟล์อะไร ตรวจอย่างไร เหลืออะไร) และไม่แปะโค้ด หัวหน้าจึงไม่ต้องอ่านไฟล์ทั้งไฟล์ซ้ำ (`AI_TEAM_REPORT` ว่าง = ปิด)
- **คำชี้แจงสอนหัวหน้าว่าต้องทำอย่างไร**: งานไม่กี่บรรทัดให้ทำเอง ใส่ไฟล์และข้อมูลที่รู้แล้วลงในงาน ตรวจด้วย test และ `git diff --stat` แทนการอ่านไฟล์ซ้ำ ส่งให้สมาชิกที่เป็นหัวหน้าทีมย่อยเฉพาะงานใหญ่ที่มีหลายส่วน และไม่ตรวจซ้ำในสิ่งที่หัวหน้าทีมย่อยตรวจแล้ว
- ทีมยิ่งลึกยิ่งเปลือง เพราะทุกชั้นต้องวางแผน แบ่งงาน และตรวจงาน ใช้ทีมย่อยกับงานใหญ่ และเก็บสมาชิกตัวเล็กไว้ในทีมของหัวหน้าเองสำหรับงานเล็ก

#### โฟลเดอร์นอกโปรเจค

ปกติทีมทำงานได้แค่ในโฟลเดอร์ที่เปิด ถ้าอยากให้สมาชิกทุกคน (รวมหัวหน้า) ใช้โฟลเดอร์อื่นได้ด้วย เช่น spec หรือข้อมูลที่อยู่นอกโปรเจค

```bash
ai team access add ~/Documents/specs
ai team access                     # ดูรายการ
ai team access rm ~/Documents/specs
```

จะส่งเป็น `--add-dir` ให้ Claude, Codex และ Antigravity และ `--include-directories` ให้ Gemini และ Qwen ส่วนสมาชิกที่กำหนดคำสั่งเอง (`ai team add <m> "..." "<คำสั่ง>"`) จะไม่ถูกเพิ่มอะไร **โฟลเดอร์ในรายการนี้ สมาชิกทุกคนอ่านและแก้ไขได้** รวมถึงผู้ให้บริการที่สมาชิกแต่ละคนส่งงานไป เพราะ CLI เหล่านี้ไม่มีโหมดอ่านอย่างเดียว `/` และโฟลเดอร์ home จะถูกปฏิเสธ ใส่เฉพาะที่ทีมต้องใช้

#### ทีมย่อยในทีม

สมาชิกแต่ละคนเป็นหัวหน้าทีมของตัวเองได้ คือแบ่งงานที่ได้รับต่อให้สมาชิกในทีมตัวเอง ตรวจงานที่ได้กลับมา แล้วรายงานกลับไปหาคนที่ส่งงานมา

```bash
ai team add work "frontend"                               # อยู่ในทีมของหัวหน้า
ai team add --of work codex:main "เขียน test ของ component"  # อยู่ในทีมของ work
ai team add --of work agy "อ่านโค้ดเก่า"
ai team ls
#   work           frontend
#     └ codex:main   เขียน test ของ component
#     └ agy          อ่านโค้ดเก่า
```

เมื่อ `work` ได้รับงาน จะได้คำชี้แจงของทีมตัวเองไปด้วย และ `ai delegate` ที่มันรันจะส่งงานไปหาสมาชิกในทีมของมันเอง (สมาชิกที่เป็น Claude จะได้รับอนุญาตให้รัน `ai delegate`, `ai team wait` และ `ai team log` ส่วน agent อื่นจะได้คำชี้แจงไว้หัวงาน) `ai team rm --of` กับ `ai team brief --of` ใช้แบบเดียวกัน

- **งานไม่ย้อนกลับขึ้นไป**: สมาชิกส่งงานให้คนที่อยู่เหนือตัวเองในสายเดียวกันไม่ได้ และลงลึกได้ไม่เกิน `AI_TEAM_MAX_DEPTH` ชั้น (ค่าเริ่มต้น 3) ชั้นสุดท้ายจะไม่ได้คำชี้แจงทีมและทำงานคนเดียว
- **แต่ละทีมทำงานทีละงาน**: ทีมย่อยมี lock ของตัวเอง จึงไม่ต้องรอ lock ที่หัวหน้าถืออยู่ (ไม่ค้าง) แต่หัวหน้าทีมย่อยไม่ควรแก้ไฟล์เดียวกับที่สมาชิกกำลังทำ
- **รองานเบื้องหลัง**: `ai team wait <log>...` พิมพ์คำตอบเมื่อเสร็จ ถ้าเกิน 9 นาทีจะออกด้วย exit 3 (`AI_TEAM_WAIT_STEP`) เพื่อไม่ให้ shell ของ agent timeout ให้รันซ้ำได้
- **Codex เป็นหัวหน้าทีมย่อยไม่ได้ถ้าไม่ปรับ**: sandbox `workspace-write` ไม่มี network และเขียน log ของ ai ไม่ได้ `ai team add --of codex:<ชื่อ>` จะบอกค่า `AI_TEAM_CODEX_OPTS` ที่ใช้เปิดให้ ถ้าต้องการ
- `ai team log` บอกว่าใครเป็นคนส่งงานแต่ละงาน (`from work`)

วิธีรันสมาชิกแบบ headless ซึ่งต่อท้ายคำสั่งที่บันทึกไว้: Claude `-p --permission-mode acceptEdits` (`AI_TEAM_CLAUDE_OPTS`) และตัวเลือกแบบประหยัด (`AI_TEAM_CLAUDE_LEAN`), Codex `exec --sandbox workspace-write --skip-git-repo-check` (`AI_TEAM_CODEX_OPTS`), Antigravity `--mode accept-edits --disable-slash-commands -p` (`AI_TEAM_AGY_OPTS`), Gemini และ Qwen `--approval-mode auto_edit -p` (`AI_TEAM_GEMINI_OPTS`), OpenCode `run` ส่วน agent อื่นให้ระบุคำสั่งเอง โดยงานจะถูกส่งเป็นอาร์กิวเมนต์ตัวสุดท้าย: `ai team add kimi "..." "kimi -p"`

- **การส่งงานให้ Codex หรือ agent อื่น คือการส่งงานและไฟล์ที่ agent นั้นอ่านไปยังผู้ให้บริการของมัน** สมาชิกจึงอยู่ในทีมก็ต่อเมื่อคุณเพิ่มเอง และ `ai team add` จะบอกว่างานไปที่ไหน
- สมาชิก Claude รันด้วย `acceptEdits` คือแก้ไฟล์ได้ แต่คำสั่ง shell ที่มันอยากรันจะถูกปฏิเสธจนกว่าคุณจะอนุญาต (เช่น `AI_TEAM_CLAUDE_OPTS="--permission-mode acceptEdits --allowedTools 'Bash(npm test)'"`) ส่วน Codex รันใน sandbox แบบ `workspace-write`

## การตั้งค่า

ไม่ต้องตั้งก็ใช้ได้ทุกอย่าง ตั้งเฉพาะครั้งเดียวได้ (`AI_TEAM_REPORT='' ai do "..."`) หรือ export ไว้ใน profile ของ shell

| ตัวแปร | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `AI_TEAM_CLAUDE_OPTS` | `--permission-mode acceptEdits` | ตัวเลือกของสมาชิก Claude (headless) |
| `AI_TEAM_CLAUDE_LEAN` | `--strict-mcp-config --disable-slash-commands --tools=Read,Edit,Write,Bash,Glob,Grep` | สมาชิก Claude แบบประหยัด; `''` = โหลดทุกอย่าง |
| `AI_TEAM_CODEX_OPTS` | `--sandbox workspace-write --skip-git-repo-check` | ตัวเลือกของสมาชิก Codex (`codex exec`) |
| `AI_TEAM_AGY_OPTS` | `--mode accept-edits --disable-slash-commands` | ตัวเลือกของสมาชิก Antigravity (`agy -p`) |
| `AI_TEAM_GEMINI_OPTS` | `--approval-mode auto_edit` | ตัวเลือกของสมาชิก Gemini หรือ Qwen |
| `AI_TEAM_REPORT` | a report of at most 15 lines | ต่อท้ายทุกงานที่กระจายไป; `''` = ไม่ต่อ |
| `AI_TEAM_HANDOFF` | `1` | สมาชิกที่โควตาหมดส่งงานต่อ; `0` = ปิด |
| `AI_TEAM_HANDOFF_MAX` | `4000` | จำนวน byte ของคำตอบที่ส่งต่อ |
| `AI_TEAM_MAX_DEPTH` | `3` | จำนวนชั้นของการกระจายงานใต้หัวหน้า |
| `AI_TEAM_WAIT` | `3600` | วินาทีที่งานรอให้โฟลเดอร์ว่าง |
| `AI_TEAM_WAIT_STEP` | `540` | วินาทีที่ `ai team wait` รอก่อนออกด้วย exit 3 |
| `AI_TEAM_KEEP_DAYS` | `30` | จำนวนวันที่เก็บ log ของงานที่เสร็จแล้ว; `0` = เก็บตลอด |
| `AI_TEAM_DISCOVER_MAX` | `1500` | จำนวน byte ของคำตอบแต่ละคนที่หัวหน้าอ่านใน `ai team discover` |
| `AI_FO_COOLDOWN` | `18000` | วินาทีที่ข้ามสมาชิกที่ติดลิมิต เมื่อไม่รู้เวลารีเซ็ต |
| `AI_FO_PROMPT` | "Continue exactly where you left off" | ข้อความที่ session ของ Claude ที่ย้ายบัญชีใช้เริ่มต่อ |
| `AI_FO_CODEX_PROMPT` | "You are taking over..." | บรรทัดแรกของบทสนทนาที่ส่งต่อเป็นข้อความ |
| `AI_FO_HANDOFF_MAX` | `60000` | จำนวน byte ของบทสนทนาที่ส่งต่อเป็นข้อความ |
| `AI_NO_FZF` |  | `1` = ใช้เมนูตัวเลขแม้ติดตั้ง fzf แล้ว |
| `AI_YES` |  | `1` = ตอบ yes ทุกคำถาม (สำหรับ script และ test) |
| `CLA_ROOT`, `CDX_ROOT` | `~/.claude-accounts`, `~/.codex-accounts` | ที่เก็บบัญชีเพิ่มเติม |

## เรื่องความปลอดภัย

- **ชื่อบัญชีและชื่อ agent ถูกตรวจทุกครั้ง** ใช้ได้เฉพาะตัวอักษร ตัวเลข `.` `_` `-` และห้ามขึ้นต้นด้วย `.` จึงไม่มีทางกลายเป็น path อย่าง `..`
- **ไม่มีการลบไฟล์ของผู้ใช้** `cla rm` ย้ายไปถังขยะเสมอ
- **ไม่ยุ่งกับรหัสผ่านหรือ token** ไม่อ่าน Keychain ไม่คัดลอก credential บน macOS หลัง `cla mv` อาจต้องล็อกอินใหม่หนึ่งครั้ง เพราะ Claude เก็บการล็อกอินผูกกับ path ของโฟลเดอร์
- **ไฟล์ JSON ของ agent อื่นแก้อย่างระวัง** ตรวจว่าเป็น JSON ที่ถูกต้องก่อนและหลังแก้ สำรองไฟล์เดิมไว้ที่ `<ไฟล์>.ai-hub.bak` หนึ่งครั้ง และสลับไฟล์ใหม่เข้าไปในครั้งเดียว (rename) โดยคงสิทธิ์ไฟล์เดิมไว้ agent ที่รันอยู่จึงไม่มีทางอ่านเจอไฟล์ที่เขียนไปครึ่งเดียว
- **รัน `cla` จากในหน้าต่าง Claude ได้** (เช่น `! cla ls`) `main` ยังหมายถึง `~/.claude` เสมอ ไม่สับสนกับบัญชีที่กำลังเปิดอยู่ `ai codex` กับ `~/.codex` ก็เช่นกัน
- **การแชร์ trust ปิดไว้เป็นค่าเริ่มต้น** เพราะการ trust โฟลเดอร์ทำให้ agent โหลด settings, hooks และ MCP server ของโฟลเดอร์นั้น repo ที่ trust ครั้งเดียวจะถูก trust ในทุก agent
- **Failover อยู่ในบัญชี Claude ของคุณเอง เว้นแต่จะเพิ่ม Codex หรือ agent อื่น** บทสนทนาจะไปถึงผู้ให้บริการอีกรายก็ต่อเมื่อคุณใส่บัญชี `codex:` หรือ agent ในลำดับเอง และตอบ `y` ตอนที่ระบบถามเท่านั้น `cla rm` เอาชื่อออกจากลำดับและจากทีมเสมอ แม้จะมี agent ชื่อเดียวกัน งานจึงไม่มีทางไปหา agent นั้นแทน
- **งานในทีมที่สมาชิกทำไม่จบเพราะโควตาหมด จะไปหาสมาชิกคนอื่นในทีมเดียวกัน** ซึ่งอาจเป็นผู้ให้บริการอีกราย แต่ก็อยู่ในทีมเพราะคุณเพิ่มเอง
- **บัญชีที่สร้างด้วย `cla add` ใช้ settings ร่วมกัน** รวมถึง hooks และ plugins ที่ตั้งไว้ใน `~/.claude/settings.json` ด้วย ถ้าใน settings มี `env` (เช่น `ANTHROPIC_API_KEY`) หรือ `apiKeyHelper` ทุกบัญชีจะใช้ค่านั้นเหมือนกันหมด ถ้าไม่ต้องการ ให้ลบลิงก์ `settings.json` ในโฟลเดอร์บัญชีนั้นแล้วสร้างไฟล์ของตัวเองแทน
- **หัวหน้าทีมรัน `ai delegate` ได้โดยไม่ต้องถาม** และสมาชิกใช้โฟลเดอร์ใน `ai team access` ได้ ซึ่งแก้ไขได้ด้วย จึงควรใส่ให้น้อยที่สุด
- **สมาชิกทีมจะได้รับงานก็ต่อเมื่อคุณเพิ่มเข้าทีมเอง** หัวหน้ามี shell อยู่แล้ว `ai delegate` จึงไม่ได้ให้สิทธิ์อะไรเพิ่มจากการรัน `codex` เองโดยตรง แต่ทำให้การส่งงานชัดเจน มี log และจำกัดอยู่แค่สมาชิกที่คุณเลือก
- **log การกระจายงานเป็นของคุณคนเดียว** ในนั้นมีงานและคำตอบฉบับเต็ม (ซึ่งมักมีโค้ด) โฟลเดอร์ทีมจึงตั้งสิทธิ์ให้อ่านได้เฉพาะคุณ (โฟลเดอร์ `700` ไฟล์ `600` ของเก่าที่สิทธิ์หลวมกว่าจะถูกปรับตอนกระจายงานครั้งถัดไป) log จะถูกลบเมื่อเก่ากว่า 30 วัน (`AI_TEAM_KEEP_DAYS`) หรือลบทันทีด้วย `ai team log --clean`
- **Failover ถามก่อนย้าย session เสมอ และค่าเริ่มต้นคือ "ไม่"** กด Enter เฉยๆ จะไม่ย้าย ต้องพิมพ์ `y` เท่านั้น เพื่อกันไม่ให้บทสนทนาหลุดจากบัญชีงานไปบัญชีส่วนตัวโดยไม่ตั้งใจ
- **บัญชีที่ `cla rm` ยังเก็บข้อมูลล็อกอินไว้ใน `~/.claude-accounts/.trash/`** (บน Linux คือ `.credentials.json`) ถ้าต้องการลบจริง ให้ลบโฟลเดอร์นั้นเอง

## ข้อจำกัด

- Failover ตรวจลิมิตจากข้อความ error สุดท้ายใน transcript ของ Claude Code และหา session จากชื่อโฟลเดอร์ที่ Claude Code ตั้งให้ ถ้า Claude Code เปลี่ยนรูปแบบสองอย่างนี้ในอนาคต อาจต้องปรับ `fo_hit_limit` และ `fo_project_keys` ใน `lib/failover.sh` ส่วนลิมิตของ Codex อ่านจากไฟล์ session (`$CODEX_HOME/sessions`) ดู `fo_codex_*` ในไฟล์เดียวกัน
- สมาชิกที่ชนลิมิตระหว่างทำงานตรวจจากบรรทัดท้ายๆ ที่มันพิมพ์ออกมา (`fo_hit_limit`) Claude และ Codex ใช้คำว่า "usage limit" ส่วนคำของ Antigravity CLI ยังตรวจสอบไม่ได้ สมาชิก `agy` ที่โควตาหมดจึงอาจล้มเหลวแทนที่จะส่งงานต่อ หัวหน้าจะเห็น error แล้วเลือกคนอื่นแทน
- ข้อมูลโควตาของ Claude ขึ้นกับว่า Claude Code เวอร์ชันที่ใช้ส่ง `rate_limits` ให้ status line หรือไม่
- ตัวเลือก headless ที่ใช้รันสมาชิกทีม (`claude -p`, `codex exec --sandbox`, `agy -p --mode`, `gemini --approval-mode`) อิงจากเวอร์ชันปัจจุบัน ถ้าตัวไหนเปลี่ยน ให้ตั้งตัวแปร `AI_TEAM_*_OPTS` หรือระบุคำสั่งของสมาชิกคนนั้นเอง
- ยังไม่รองรับ Windows แบบ native (ใช้ผ่าน WSL ได้)
